# trail-pilot

A single-file Cesium web app that turns any GPX route into an offline, phone-friendly 3D map with break detection, an elevation scrubber, and (coming) real-time GPS route-following.

## Quick start (the agent-free loop)

```sh
./run.sh input/your-run.gpx
```

That's the whole loop: it converts the GPX to `route_data.json` (breaks + start-location timezone, detected automatically) and serves the folder — it prints a `localhost` URL for your machine and a LAN URL for your phone on the same Wi-Fi. Stop with Ctrl-C.

Manual, if you prefer:

1. Convert:
   ```sh
   node build/gpx2route.js input/your-run.gpx [--tz=Area/Location]
   ```
2. Serve the folder with any static file server (`python3 -m http.server`) and open `index.html`.

No build step, no bundler, no agent. `index.html` is one self-contained file that reads `route_data.json` and renders the route, breaks, elevation profile, and controls.

## What it does

- **Route track** — the full GPX track, clamped to terrain, with a progress glow.
- **Breaks** — automatically detected from stretches where the runner is nearly stationary (total GPS drift under 200 m over a 10-minute window). Each break is a tappable pin with its duration and start time.
- **Elevation scrubber** — a Gaia-style time-based elevation profile; drag or tap to scrub, with a live position marker.
- **Camera controls** — tilt up/down, rotate, and a compass that resets to north (all pivoting around screen center, like two-finger orbit).
- **Mobile** — full-bleed map, collapsed break list, tap-to-pick, double-tap to zoom, touch scrubbing.
- **Times** — converted from the GPX's UTC timestamps to the local timezone of the route's start point, auto-detected from the start coordinates (see Timezone).

## File layout

```
index.html               the app (Cesium via CDN, single file)
run.sh                   one-shot: convert + serve
route_data.json          generated by build/gpx2route.js (gitignored)
build/gpx2route.js       GPX to route_data.json converter
build/tz-grid.json       offline coord-to-IANA-timezone grid (generated artifact)
build/gen-tz-grid.js     regenerates build/tz-grid.json (rarely needed)
input/                   drop GPX files here
```

## Break detection

`build/gpx2route.js` scans the track with a sliding 10-minute window. A point is "stationary" if the total distance traveled within the next 10 minutes is under `BREAK_DRIFT_M` (default 200 m). Consecutive stationary points are merged into breaks, and only breaks longer than `MIN_BREAK_SEC` (default 10 min) are kept. The detected breaks are printed with each conversion so you can sanity-check them.

Tune the three constants at the top of `build/gpx2route.js` if your GPX has a different point density (e.g. a smartwatch that logs every second vs. every 10 s).

## Timezone

GPX timestamps are UTC. The converter auto-detects the IANA timezone of the start point from a precomputed boundary grid (`build/tz-grid.json`, 0.25° cells derived from timezone-boundary-builder data) and writes it to `route_data.json`; `index.html` uses it. This handles the tricky cases correctly — e.g. eastern Kentucky is `America/New_York` even though its longitude suggests Central — and works for routes anywhere in the world.

- Override per-run: `node build/gpx2route.js input/your-run.gpx --tz=Europe/Berlin`.
- The grid has roughly 20 km resolution at boundaries; if a route starts right on a timezone border and the detection looks wrong, use `--tz`.
- `build/tz-grid.json` is a generated artifact checked in so the loop stays offline. Regenerate it (needs network) with `node build/gen-tz-grid.js`.
- Data files without a `timezone` field fall back to the `LOCAL_TZ` constant in `index.html`.

## Real-time GPS (planned)

The next feature is live GPS tracking / route following: the app will read the device's location and show progress along the route, with turn-by-turn cues. The data model (route points with cumulative time offsets) is already in place for this.
